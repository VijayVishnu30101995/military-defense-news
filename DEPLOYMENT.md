# Deployment

Live links and the services this project runs on. For setup steps, see the
"Free deployment" section in `README.md`. No passwords, tokens, or connection
strings are stored here — only Render and Neon have those, as private
environment variables.

## Services used

| Service | Used for | Plan | Notes |
|---|---|---|---|
| [Cloudflare Pages](https://pages.cloudflare.com) | Hosting the static frontend (`frontend/`) | Free | Auto-deploys from the `main` branch. Publish folder is pinned by `wrangler.toml` at the repo root (`pages_build_output_dir = "frontend"`) — the dashboard's own build-output setting wasn't reliable. |
| [Render](https://render.com) | Hosting the FastAPI backend | Free Web Service | Service name `military-defense-news-api`, region Oregon (US) — the free tier doesn't offer an Asia region. Deploys from `render.yaml` at the repo root. Sleeps after ~15 min idle (see cron-job.org below). |
| [Neon](https://neon.tech) | Postgres database | Free | Project region: Asia Pacific 1 (Singapore), database `neondb`. Data persists indefinitely on the free tier (unlike Render's own free Postgres, which expires). |
| [cron-job.org](https://cron-job.org) | Keeps the backend awake | Free | Pings `https://military-defense-news-api.onrender.com/health` every 10 minutes, so Render doesn't sleep and the news-collection scheduler keeps running. |

## Environment variables (set in Render, not in the repo)

- `DATABASE_URL` — Neon connection string (`postgresql+psycopg://...`)
- `SECRET_KEY` — auto-generated by the Render blueprint
- `ADMIN_EMAIL` — defaults to `admin@defensebrief.com`
- `ADMIN_PASSWORD` — the admin login password; changing it resets the admin password on the next restart
- `APP_ENV`, `NEWS_TIMEZONE`, `PYTHON_VERSION` — see `render.yaml`

## Updating the live site

Push to `main` on GitHub. Cloudflare Pages and Render both redeploy
automatically. The frontend has no build step; the backend runs
`alembic upgrade head` before starting, so new migrations apply on deploy.
